HOW WE KEEP IT HONEST

A change should never hide a difference.

  1. Push either app. CI records source hashes, mapped files and recent commits.
  2. Changed since review? The assessment becomes “Needs review”. The previous notes stay visible.
  3. Review both implementations. Update the behavior, tests and matching feature IDs before renewing the review.
  4. Publish the evidence. Pages refreshes after the snapshot workflow; scheduled main reconciliation runs every 15 minutes as a fallback.

What automation cannot decide

A commit cannot prove that a screen works, a payment settled, or two answers agree. Reviews and real tests provide that evidence.

“Needs review” is an honest unknown. New features must be added to the shared catalog. Native billing, permissions and accessibility can differ when the reason is recorded.
